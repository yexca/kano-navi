Kano Navi v0.1.2 adds native Anthropic model support, faster and more reliable
dashboard loading, bounded public projections, and stronger snapshot, source,
and media recovery. The release also expands the regression suite and documents
the production and development boundaries more clearly.

## Dashboard and history

- Dashboard requests recover from failed or slow responses while retaining the
  last known snapshot, and revision changes refresh loaded calendar pages
  atomically.
- Public dashboard previews stay bounded for predictable response sizes. Full
  calendar history remains available through the calendar API and paginated
  admin views.
- Stream and event selection uses the actual linked video identity and end
  time, including watch, live, short, and share URL forms. The spotlight keeps
  the correct upcoming item across Japan-time boundaries.
- Public health, profile-media, HTTP, and MCP responses expose visitor-safe
  projections instead of database labels, internal counters, or raw upstream
  diagnostics.

## Synchronization and media

- X and YouTube work queues retry durable pending items fairly, retain known
  snapshots when a source fails, and keep request and response sizes bounded.
- Schedule extraction waits for every declared image and keeps image review
  state attached to the matching source asset. Manual verdicts and selected
  profile media survive automatic refreshes and repair incomplete metadata.
- YouTube reservation checks reject incomplete watch details so a later run can
  retry them, while equivalent public video links continue to share one stream
  identity.
- Media downloads validate redirects and cache paths, and complete post-media
  updates reconcile additions, replacements, removals, and ordering without
  discarding a failed snapshot.

## Providers and operator console

- The provider center supports native Anthropic Messages requests and paginated
  model discovery, with capability-aware routing and provider icons.
- OpenAI Responses, Chat Completions, and Anthropic Messages routes use bounded
  requests, retries, response bodies, and redirect handling. Provider keys stay
  encrypted and are never returned by the admin API.
- Schedule image review, model routes, workflow outcomes, profile media, and
  source failures show clearer progress and preserve manual operator decisions.

## Runtime and development

- Production Docker packaging includes the shared runtime modules used by the
  server and history pages, and the container keeps the existing data snapshot
  across upgrades.
- Compression, validators, polling backoff, and request deadlines reduce page
  latency and prevent stalled source or model requests from blocking recovery.
- New synthetic regression, HTTP performance, polling, UI, and production
  smoke fixtures cover the release contracts without contacting live sources.
